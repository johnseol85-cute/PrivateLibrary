# 01. 대화 맥락과 결정 사항

> 출처: 2026-10-07, IDML2Epub 저장소 세션에서 나눈 기획 대화. 이 문서는 그 대화를 이어 가기 위한 요약이다.

## 1. 대화 흐름 요약

1. **출발점**: 사용자가 Scriptorium AI(aipastors.org) 스크린샷을 보여 주며 "이런 라이브러리를 구축하고 싶다. 개인용이지만 나중에 상업용으로 바뀔 수도 있다"고 함.
2. **담을 자료**: 공개 원전 + 개인 소장 자료 **둘 다**. 우선은 공개 원전이 기본.
3. **참고 사이트 분석**: 대시보드, 원전 검색, 분류 목록 화면을 분석함 → [02](02-reference-analysis.md).
   - 자료는 자체 서버에 복사해 두고, 원 출처 링크를 따로 제공하는 구조로 추정.
4. **수집 원칙**: 구조화 데이터(XML/JSON) 우선, txt 변환이 목표가 아님(좌표가 사라지므로). PDF는 최후 수단이며 주로 개인 자료용.
5. **스냅샷 보관**: 특정 버전을 받아 압축 보관하면 원본이 바뀌거나 사라져도 내 자료로 유지됨(CC 라이선스는 철회 불가). 텍스트는 용량이 작음.
6. **인프라 논의** → [03](03-architecture.md)
   - Google Drive는 서버가 될 수 없음(코드 실행 불가). **보관소**로 사용.
   - 사이트는 **Vercel**, 검색 DB는 **Turso**(Drive에 있는 DB 파일의 사본).
   - "Turso가 Drive를 직접 읽는" 구조는 불가능. Drive(원본) → Turso(사본) 단방향 동기화가 정답.
   - 비공개: 구글 로그인으로 **본인 계정만** 허용.
7. **범위 축소 (중요)**: 사용자가 "자료가 너무 많은 것도 복잡하다"며 방향을 좁힘.
   > 우선 오픈 소스 가운데 **히브리어·헬라어 성경 원전을 정확하게** 볼 수 있고, 그걸 **한국어로도** 볼 수 있는 것. **성서에 대한 기초적인 주해**부터 시작.
8. **방법론 조사 요청**: 옥스퍼드·예일·하버드·케임브리지·시카고·에모리 등에서 성서학을 어떻게 가르치는지 조사하고, 그 기초 방법론에 맞추어 라이브러리와 연구 사이트를 기획 → [05](05-methodology-research.md), [06](06-data-sources.md).
9. **작업 규칙**: "작업에 바로 들어가는 것보다 기획을 정확하게 하는 게 중요. 작업은 내가 진행하라고 할 때."
10. 대화 맥락 전체를 이 저장소(PrivateLibrary)로 옮김.
11. **목표 재확인 (PrivateLibrary 세션, 2026-10-07)**: 사용자가 "성경 원전을 탐구하는 **라이브러리**를 우선 만드는 게 목표"라고 정정함.
    → "주해 작업대"(주해 7단계 화면, 주해 노트)는 1차 목표에서 빼고 **나중으로 보류**. 방법론 조사([05](05-methodology-research.md))는 참고 자료로만 남김.

## 2. 확정된 사항

| 항목 | 결정 |
|---|---|
| 1차 목표 | **성경 원전 탐구 라이브러리**: 히브리어 구약 + 헬라어 신약 원전을 정확하게 읽고, 한국어로 함께 보고, 단어·형태·사전·검색으로 탐구 |
| 사이트 성격 | **원전 라이브러리 우선**. "주해 작업대"는 보류(이후 확장) |
| 호스팅 | **Vercel** (`*.vercel.app`) |
| 보관소 | **Google Drive** — 원본, 정제본, 빌드 결과(DB 파일), 개인 자료 |
| 검색 DB | **Turso** — Drive의 `library.db` 사본. Drive가 기준(원본) |
| 비공개 | 구글 로그인, 허용 이메일 = 본인만. 검색엔진 차단. 저장소 private |
| 수집 방식 | 버전 고정 스냅샷 + 출처 기록(출처·URL·버전·날짜·라이선스) |
| 라이선스 관리 | 데이터 단위로 라이선스 태그와 공개 등급(공개 / 제한(NC) / 격리(개인)) 부여 — 상업화 대비 |
| 좌표 체계 | 성경은 OSIS식 참조(예: `Rom.3.25`) + 단어 단위 ID |

## 3. 보류된 것 (나중에)

- **주해 작업대**(주해 7단계 화면, 주해 노트, 구조 트리) — 라이브러리 완성 후 검토
- 교부·종교개혁 문헌, 고대근동 자료, 칠십인역(LXX)
- 개인 소장 PDF·EPUB "내 서재"
- AI 질문·인용 검증(RAG), 에이전트, 루틴
- 목회 콘텐츠 생성 기능(쇼츠, 카드뉴스, 악보 등) — 범위 밖

## 4. 열린 질문 (사용자 답변 대기)

목표 재확인(라이브러리 우선) 후 정리한 질문. 기존 1번(방법론 관점)은 주해 작업대 보류로 지금은 불필요.

1. **탐구 기능의 범위** — 라이브러리 1차에 무엇까지 넣을지:
   원문 읽기 · 한국어 병행 · 단어 클릭(원형·형태·사전 뜻) · 용례(같은 단어가 나오는 곳) · 원어/한국어 검색 · 출처 링크
2. **원어 설명 수준** — 형태·문법 설명을 학습자용(친절)으로 할지, 연구자용(간결)으로 할지?
3. **한국어 번역** — 개역한글(1961, 저작권 만료로 알려짐)을 기본 번역으로 확정할지?
4. **범위** — 데이터는 66권 전체로 들어오므로 전권을 싣되, 검수는 샘플(예: 룻기 + 빌립보서)로 먼저 할지?
