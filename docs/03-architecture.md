# 03. 아키텍처: Google Drive · Turso · Vercel

## 1. 구조

```
        [Google Drive]  보관소 (원본 · 작업 공간 · 백업) ← 기준
        ├ 01_원본/   받은 그대로, 버전·날짜 표기, 압축 + SOURCES.md
        ├ 02_정제/   공통 형식 (좌표 + 라이선스 태그)
        ├ 03_내서재/ 개인 PDF·EPUB (나중)
        └ 04_빌드/   library.db  ← 02에서 언제든 재생성 가능
                │                                │
                │ ① 빌드한 DB를 올림(단방향)       │ ③ "원본 열기" 시
                ▼                                │    그 파일만 불러옴
        [Turso]  검색용 DB (library.db 사본)      │
                │ ② 검색·조회                     │
                ▼                                ▼
        [Vercel]  my-library.vercel.app  ← 구글 로그인(본인만)
                ▲
        PC · 휴대폰
```

| 구성 | 역할 |
|---|---|
| Google Drive | 모든 자료의 원본. 데이터 작업은 여기서 |
| Turso | 검색 전용 사본. SQLite 호환이라 `library.db`를 그대로 올림. 벡터 검색 지원 |
| Vercel | 사이트, 로그인, 화면 |
| GitHub (private) | 코드와 기획 문서 |

## 2. 왜 이렇게 나누나 (논의 결과)

- **Drive는 서버가 될 수 없다**: 파일 보관만 하고 코드를 실행하지 않음. 웹 호스팅 기능은 2016년 종료. API로 DB를 읽으면 매번 전체를 내려받아야 해서 느리고 호출 제한에 걸림.
- **Turso가 Drive를 직접 읽을 수 없다**: DB 엔진은 데이터를 자기 서버에 갖고 있어야 함. 따라서 Drive → Turso **단방향 동기화**.
- **사본은 비효율이 아니다**: 텍스트 DB는 작고, 방향이 한쪽뿐이라 어긋나지 않으며, Turso가 날아가도 Drive에서 다시 올리면 됨.
- **Vercel에 DB 파일을 같이 싣지 않는 이유**: 함수 번들 크기 제한(수백 MB) 때문.

검토했던 대안:

| 방식 | 평가 |
|---|---|
| Drive(원본) → Turso(사본) → Vercel | **채택** |
| Vercel이 Drive에서 DB를 직접 받아 씀 | 느리고 불안정 |
| Turso를 원본으로 | 데이터 작업이 어려워짐 |
| 작은 클라우드 서버(Fly.io, Hetzner 등) | 가능. 자료가 매우 커지면 재검토 |
| 내 PC + Drive 동기화 + Tailscale | 무료·완전 비공개. PC가 켜져 있어야 함 |
| Google Apps Script | 실행 시간·속도 제한으로 부적합 |

## 3. 비공개 설정

| 층 | 방법 |
|---|---|
| 1 | 검색엔진 수집 차단 (noindex) |
| 2 (핵심) | **구글 로그인 필수, 허용 이메일 = 본인만** — 주소를 알아도 못 들어옴 |
| 3 (선택) | Cloudflare Access 같은 출입 관문 |
| 4 | GitHub 저장소 private, Drive 폴더 비공유 |

Vercel 자체 접근 보호는 요금제에 따라 범위가 달라서, 앱 로그인을 기본으로 둔다.

## 4. 용량과 비용

Turso 요금제 (2026년, 제3자 자료 기준 — 시작 시 공식 확인 필요):

| 요금제 | 월 | 저장 | 월 읽기(행) |
|---|---|---|---|
| Free | $0 | 5GB | 5억 |
| Developer | $4.99 | 9GB | 25억 |

- 성경 원어 + 형태소 + 사전 + 한국어: 1GB 미만 예상 → **Free로 충분**.
- 나중에 AI 벡터 색인을 넣으면 Developer 고려.
- **읽기 한도 주의**: 색인 없이 전체를 훑는 검색은 한도를 빨리 씀 → FTS 색인과 좌표 색인을 설계에 포함.
- **Turso에는 텍스트와 색인만.** PDF·이미지·원본 압축 파일은 Drive에만.
- Vercel Hobby(무료)는 **개인·비상업 전용**. 상업화 시 Pro로 전환.

## 5. 수집·보관 원칙

- 버전 고정 스냅샷(릴리스 압축본 또는 특정 커밋). Git 전체 이력은 받지 않음.
- 필요한 파일만 남기고 압축 보관.
- 출처 기록: 출처명, URL, 버전(커밋 해시), 받은 날짜, 라이선스, 공개 등급.
- 다시 만들 수 있는 것(빌드 결과, 벡터 색인)은 원본으로 취급하지 않음.
- 확보 우선순위: A 구조화 데이터(XML/JSON/OSIS/USFM) > B HTML·텍스트 > C 디지털 PDF > D 스캔 PDF(OCR).
